A local agent that
actually uses tools.

Building and debugging a private agentic pentesting stack with Hermes, Ollama, qwen3.5:9b-64k and Exegol—then proving that tool calls produce real execution rather than plausible text.

TL;DR

The model could generate native tool calls through Ollama, but Hermes initially returned commands as text instead of executing them. Direct API testing isolated the model and transport; mitmproxy confirmed that Hermes sent tool schemas; aligning Ollama and Hermes on a dedicated 64K context produced structured terminal execution in the lab. The stable architecture keeps Ollama on macOS, runs Hermes inside Exegol, and persists custom tooling through my-resources.

01 / ARCHITECTURE

Keep inference on the host and operations in Exegol

The final design separates local inference from the disposable security environment. Ollama keeps native Apple Metal acceleration on macOS; Hermes reaches it through host.docker.internal and operates the tools available inside Exegol.

02 / COMPONENTS

A model is not an agent

The LLM

The language model is the reasoning component. It can generate a command, but generation is not execution.

reasoning versus action
LLM → "pwd"                         # generated text
LLM → tool_call("terminal", "pwd")  # structured intent
harness → shell → stdout             # observed execution

Ollama

Ollama loads the model, manages inference and exposes both its native API and an OpenAI-compatible interface at /v1.

Hermes

Hermes is the agent harness around the LLM. It supplies the system prompt, tool definitions, execution loop, file operations, context management and observations that allow the model to act on an environment.

The effective agent is the model, inference configuration, harness, tools and hardware working as one system.

04 / PERSISTENCE

Move custom tooling outside the disposable container

Exegol maps the host's ~/.exegol/my-resources/ directory into the container at /opt/my-resources. A persistent layout can separate the launcher, runtime and configuration:

/opt/my-resources
/opt/my-resources/
├── bin/
│   └── hermes
├── tools/
│   └── hermes/
│       └── venv/
└── config/
    └── hermes/

The persistent launcher contains:

/opt/my-resources/bin/hermes
#!/bin/sh
exec /opt/my-resources/tools/hermes/venv/bin/hermes "$@"

Exegol / verify persistence

$ chmod +x /opt/my-resources/bin/hermes
Expected output: no stdout; exit status 0

$ which hermes
Expected output:
/opt/my-resources/bin/hermes

Restart the container and repeat which hermes. The same path is the expected result. Keep secrets out of images and version control, restrict permissions, and persist only what the deployment requires.

05 / FAILURE MODE

Plausible text looked like execution

The first setup appeared functional: the model understood requests and returned commands. The missing evidence was the tool event itself.

Observed responseInterpretation
bash
pwd		SIMULATED Command-shaped text only
💻 preparing terminal…
💻 $ pwd		EXECUTED Harness invoked the tool

A stronger test requires unpredictable, environment-derived output:

prompt sent to Hermes
Use exclusively the terminal tool.

Execute:
cat /proc/sys/kernel/random/uuid && pwd && hostname

Do not simulate the output. Return the real stdout.

Expected Hermes evidence

💻 preparing terminal…
💻 $ cat /proc/sys/kernel/random/uuid && pwd && hostname

Expected output (values vary):
<random UUID>
<current working directory>
<container hostname>
Safety boundary

Use only an isolated lab or systems you are explicitly authorized to test. Verify state changes independently and never use user data as a tool-execution fixture.

06 / TOOL CALLING

Test the model and transport independently

A direct request to Ollama removed Hermes, Docker tooling and the shell from the immediate fault domain:

host / direct compatible API test

$ curl -s http://localhost:11434/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model":"qwen3.5:9b",
    "messages":[{"role":"user","content":"Execute pwd using the terminal tool."}],
    "tools":[{"type":"function","function":{
      "name":"terminal",
      "description":"Execute a command in the terminal",
      "parameters":{"type":"object","properties":{"command":{"type":"string"}},"required":["command"]}
    }}]
  }'

Expected output (relevant fields):
{"tool_calls":[{"type":"function","function":{"name":"terminal",
"arguments":"{\"command\":\"pwd\"}"}}],"finish_reason":"tool_calls"}

This result established that the model could emit a native call and that Ollama could transport it through the compatible API. It did not yet establish that Hermes would execute the function.

07 / WIRE EVIDENCE

Inspect what Hermes actually sends

mitmproxy was inserted temporarily as a reverse proxy between Hermes and Ollama:

host / capture Hermes requests

$ mitmdump --mode reverse:http://127.0.0.1:11434 \
  --listen-host 127.0.0.1 --listen-port 11435 \
  -w ~/hermes-ollama.flow

Expected output (abridged):
Proxy server listening at http://127.0.0.1:11435
temporary Hermes endpoint
base_url: http://127.0.0.1:11435/v1

host / inspect saved flow

$ mitmweb -r ~/hermes-ollama.flow

Expected output (abridged):
Web server listening at http://127.0.0.1:8081

The capture contained a populated tools array. Hermes was sending tool definitions, so the failure was not simply a missing schema.

Sensitive evidence

Proxy flows can contain prompts, system instructions, schemas, hostnames, secrets and assessment data. Protect, sanitize and retain them according to the lab or engagement evidence policy.

08 / CONTEXT

Align Ollama and Hermes at 64K

The original configuration allocated an unnecessarily aggressive context for the available hardware. The successful lab used a dedicated 64K model variant.

host / create 64K model variant

$ cat > ~/Modelfile-qwen35-64k <<'EOF'
FROM qwen3.5:9b
PARAMETER num_ctx 64000
EOF
Expected output: no stdout; exit status 0

$ ollama create qwen3.5:9b-64k -f ~/Modelfile-qwen35-64k
Expected output (final line):
success

host / verify model and effective context

$ ollama ls
Expected output (relevant rows):
NAME
qwen3.5:9b-64k
qwen3.5:9b

$ ollama run qwen3.5:9b-64k "Reply only with: ready"
Expected output:
ready

$ ollama ps
Expected output (relevant columns):
NAME                CONTEXT
qwen3.5:9b-64k      64000

Hermes was then configured with context_length: 64000. In the observed lab, this alignment changed behavior from frequent command-shaped text to structured tool execution.

64K did not magically teach Qwen tool calling. The direct API test had already proved that capability. The evidence supports a narrower conclusion: agentic reliability depends on the complete inference configuration.

What does 6.43K/64K mean?

The visible conversation is only part of the working context. System instructions, tool schemas, skills, prior observations and agent state also consume tokens. A new run can therefore begin with several thousand tokens already occupied.

context indicator
qwen3.5:9b-64k │ 6.43K/64K │ 10%

≈ 6,430 tokens occupied
≈ 57,570 tokens available

Larger is not automatically better. KV-cache growth can create memory pressure, swap and severe latency. In this lab, a larger 14B configuration with a large context exceeded the practical capacity of an 18 GB Apple Silicon system.

09 / OPERATIONAL MEMORY

Use context as working memory, not an evidence store

Long-running work should externalize structured state instead of keeping hours of raw output in the prompt:

bounded engagement workspace

├── services.json

Before considering extended autonomy, run a bounded endurance test in an isolated lab. Validate scope retention, timeouts, error handling, evidence capture, command correctness and stop controls. Do not leave the agent unattended against a real environment until those properties have been demonstrated.

10 / LESSONS LEARNED

What survived the debugging process

01

Require execution evidence. Plausible output is not proof; verify visible tool events and environment-derived results.

02

Test each layer independently. Direct API requests and proxy captures reduce a large fault domain to observable components.

03

The harness matters. A capable model with a misaligned harness or inference configuration can behave like a poor agent.

04

Align effective context. Verify the loaded Ollama context and the client expectation instead of trusting configuration alone.

05

Prefer stability over maximum size. A stable 9B model at 64K is more useful than a larger model that makes the workstation unusable.

06

Persist state deliberately. Use my-resources for tooling and durable files for scope, results and evidence.

07

Tool calling is not autonomy. Real pentesting also requires approvals, audit, secrets handling, strict boundaries, timeouts and an emergency stop.

11 / CONCLUSION

A local agent is a system, not a model

The working lab combined qwen3.5:9b-64k for reasoning, Ollama for local inference, Hermes for the tool loop, Exegol for the operational environment, my-resources for persistence and mitmproxy for temporary wire-level visibility.

Aligning the server and harness at 64K turned an apparently capable but non-executing setup into one that produced structured tool calls and real terminal evidence. The next responsible milestone is a controlled endurance test with strict scope, persistent state, auditable actions and reproducible results—not unrestricted autonomy.

LAB RESULT: WORKING BASELINE

Tool calling and terminal execution were observed after context alignment. Production readiness, autonomous safety and broad reliability were not established by this lab.
