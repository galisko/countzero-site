Un agente local que
realmente usa herramientas.

Construcción y depuración de un stack privado de pentesting agéntico con Hermes, Ollama, qwen3.5:9b-64k y Exegol, hasta demostrar que las llamadas a herramientas producen ejecución real y no texto convincente.

TL;DR

El modelo podía generar llamadas nativas a herramientas a través de Ollama, pero Hermes inicialmente devolvía los comandos como texto en lugar de ejecutarlos. La prueba directa de la API aisló el modelo y el transporte; mitmproxy confirmó que Hermes enviaba los esquemas de herramientas; alinear Ollama y Hermes sobre un contexto dedicado de 64K produjo ejecución estructurada en el terminal del laboratorio. La arquitectura estable mantiene Ollama en macOS, ejecuta Hermes dentro de Exegol y persiste las herramientas personalizadas mediante my-resources.

01 / ARQUITECTURA

Mantener la inferencia en el host y la operación en Exegol

El diseño final separa la inferencia local del entorno de seguridad desechable. Ollama conserva la aceleración nativa de Apple Metal en macOS; Hermes lo alcanza mediante host.docker.internal y opera las herramientas disponibles dentro de Exegol.

02 / COMPONENTES

Un modelo no es un agente

El LLM

El modelo de lenguaje es el componente de razonamiento. Puede generar un comando, pero generarlo no equivale a ejecutarlo.

razonamiento frente a acción
LLM → "pwd"                         # texto generado
LLM → tool_call("terminal", "pwd")  # intención estructurada
harness → shell → stdout             # ejecución observada

Ollama

Ollama carga el modelo, administra la inferencia y expone tanto su API nativa como una interfaz compatible con OpenAI bajo /v1.

Hermes

Hermes es el agent harness que rodea al LLM. Aporta el system prompt, las definiciones de herramientas, el bucle de ejecución, las operaciones de archivos, la gestión del contexto y las observaciones que permiten al modelo actuar sobre un entorno.

El agente efectivo es el modelo, la configuración de inferencia, el harness, las herramientas y el hardware funcionando como un único sistema.

03 / INSTALACIÓN Y CONEXIÓN

Instalar Hermes y alcanzar Ollama en el host

Revisa cualquier instalador remoto antes de ejecutarlo y fija una revisión de confianza cuando la reproducibilidad sea importante.

host / instalar Hermes

$ curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

Salida esperada (resumida):
Hermes Agent installed successfully
Run: hermes

El texto exacto del instalador puede cambiar. La comprobación fiable es que el CLI se resuelva y devuelva su información de uso.

host / verificar CLI

$ hermes --help

Salida esperada (resumida):
Usage: hermes [OPTIONS] COMMAND [ARGS]...

Desde Exegol, comprueba la ruta hasta Ollama en el host:

Exegol / conectividad con Ollama

$ curl -s http://host.docker.internal:11434/api/tags

Salida esperada (estructura):
{"models":[{"name":"qwen3.5:9b-64k",...}]}

Configura el endpoint compatible personalizado mediante Hermes:

Exegol / configuración

$ hermes setup

Salida esperada (interactiva):
Select provider: Custom / OpenAI-compatible
Base URL: http://host.docker.internal:11434/v1
Model: qwen3.5:9b-64k
configuración representativa del modelo en Hermes
model:
  default: qwen3.5:9b-64k
  provider: custom
  base_url: http://host.docker.internal:11434/v1
  context_length: 64000
  api_mode: chat_completions

Las claves de configuración pueden variar entre versiones de Hermes. Confírmalas contra el archivo generado por la versión instalada.

04 / PERSISTENCIA

Sacar las herramientas personalizadas del contenedor desechable

Exegol mapea el directorio ~/.exegol/my-resources/ del host dentro del contenedor como /opt/my-resources. Un layout persistente puede separar el launcher, el runtime y la configuración:

/opt/my-resources
/opt/my-resources/
├── bin/
│   └── hermes
├── tools/
│   └── hermes/
│       └── venv/
└── config/
    └── hermes/

El launcher persistente contiene:

/opt/my-resources/bin/hermes
#!/bin/sh
exec /opt/my-resources/tools/hermes/venv/bin/hermes "$@"

Exegol / verificar persistencia

$ chmod +x /opt/my-resources/bin/hermes
Salida esperada: sin stdout; código de salida 0

$ which hermes
Salida esperada:
/opt/my-resources/bin/hermes

Reinicia el contenedor y repite which hermes. La misma ruta es el resultado esperado. Mantén los secretos fuera de las imágenes y del control de versiones, restringe los permisos y persiste únicamente lo necesario.

05 / MODO DE FALLO

El texto convincente parecía ejecución

La primera configuración parecía funcional: el modelo entendía las solicitudes y devolvía comandos. La evidencia ausente era el propio evento de herramienta.

Respuesta observadaInterpretación
bash
pwd		SIMULADO Solo texto con forma de comando
💻 preparing terminal…
💻 $ pwd		EJECUTADO El harness invocó la herramienta

Una prueba más fuerte exige una salida impredecible derivada del entorno:

prompt enviado a Hermes
Usa exclusivamente la herramienta de terminal.

Ejecuta:
cat /proc/sys/kernel/random/uuid && pwd && hostname

No simules la salida. Devuelve el stdout real.

Evidencia esperada en Hermes

💻 preparing terminal…
💻 $ cat /proc/sys/kernel/random/uuid && pwd && hostname

Salida esperada (los valores varían):
<UUID aleatorio>
<directorio de trabajo actual>
<hostname del contenedor>
Límite de seguridad

Utiliza únicamente un laboratorio aislado o sistemas para los que tengas autorización explícita. Verifica los cambios de estado de forma independiente y nunca uses datos del usuario como fixture de ejecución.

06 / TOOL CALLING

Probar el modelo y el transporte de forma independiente

Una solicitud directa a Ollama eliminó Hermes, las herramientas de Docker y el shell del dominio de fallo inmediato:

host / prueba directa de la API compatible

$ curl -s http://localhost:11434/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model":"qwen3.5:9b",
    "messages":[{"role":"user","content":"Execute pwd using the terminal tool."}],
    "tools":[{"type":"function","function":{
      "name":"terminal",
      "description":"Execute a command in the terminal",
      "parameters":{"type":"object","properties":{"command":{"type":"string"}},"required":["command"]}
    }}]
  }'

Salida esperada (campos relevantes):
{"tool_calls":[{"type":"function","function":{"name":"terminal",
"arguments":"{\"command\":\"pwd\"}"}}],"finish_reason":"tool_calls"}

Este resultado estableció que el modelo podía emitir una llamada nativa y que Ollama podía transportarla mediante la API compatible. Todavía no demostraba que Hermes ejecutaría la función.

07 / EVIDENCIA EN TRÁNSITO

Inspeccionar lo que Hermes envía realmente

mitmproxy se insertó temporalmente como reverse proxy entre Hermes y Ollama:

host / capturar solicitudes de Hermes

$ mitmdump --mode reverse:http://127.0.0.1:11434 \
  --listen-host 127.0.0.1 --listen-port 11435 \
  -w ~/hermes-ollama.flow

Salida esperada (resumida):
Proxy server listening at http://127.0.0.1:11435
endpoint temporal de Hermes
base_url: http://127.0.0.1:11435/v1

host / inspeccionar el flujo guardado

$ mitmweb -r ~/hermes-ollama.flow

Salida esperada (resumida):
Web server listening at http://127.0.0.1:8081

La captura contenía un array tools poblado. Hermes estaba enviando las definiciones de herramientas, por lo que el fallo no era simplemente la ausencia del esquema.

Evidencia sensible

Los flujos del proxy pueden contener prompts, instrucciones de sistema, esquemas, hostnames, secretos y datos del assessment. Protégelos, sanitízalos y consérvalos de acuerdo con la política de evidencias.

08 / CONTEXTO

Alinear Ollama y Hermes en 64K

La configuración original asignaba un contexto innecesariamente agresivo para el hardware disponible. El laboratorio que funcionó utilizó una variante dedicada de 64K.

host / crear variante de modelo 64K

$ cat > ~/Modelfile-qwen35-64k <<'EOF'
FROM qwen3.5:9b
PARAMETER num_ctx 64000
EOF
Salida esperada: sin stdout; código de salida 0

$ ollama create qwen3.5:9b-64k -f ~/Modelfile-qwen35-64k
Salida esperada (última línea):
success

host / verificar modelo y contexto efectivo

$ ollama ls
Salida esperada (filas relevantes):
NAME
qwen3.5:9b-64k
qwen3.5:9b

$ ollama run qwen3.5:9b-64k "Reply only with: ready"
Salida esperada:
ready

$ ollama ps
Salida esperada (columnas relevantes):
NAME                CONTEXT
qwen3.5:9b-64k      64000

Hermes se configuró después con context_length: 64000. En el laboratorio observado, esta alineación cambió el comportamiento desde texto con forma de comando hacia ejecución estructurada de herramientas.

64K no enseñó mágicamente tool calling a Qwen. La prueba directa de la API ya había demostrado esa capacidad. La evidencia sostiene una conclusión más estrecha: la fiabilidad agéntica depende de la configuración completa de inferencia.

¿Qué significa 6.43K/64K?

La conversación visible es solo una parte del contexto de trabajo. Las instrucciones de sistema, los esquemas de herramientas, las skills, las observaciones previas y el estado del agente también consumen tokens. Una ejecución nueva puede comenzar con varios miles de tokens ya ocupados.

indicador de contexto
qwen3.5:9b-64k │ 6.43K/64K │ 10%

≈ 6,430 tokens ocupados
≈ 57,570 tokens disponibles

Más grande no significa automáticamente mejor. El crecimiento de la KV cache puede provocar presión de memoria, swap y latencia severa. En este laboratorio, una configuración 14B con un contexto grande superó la capacidad práctica de un equipo Apple Silicon con 18 GB.

09 / MEMORIA OPERATIVA

Usar el contexto como memoria de trabajo, no como almacén de evidencia

El trabajo prolongado debe externalizar estado estructurado en lugar de mantener horas de salida cruda dentro del prompt:

workspace delimitado del engagement
/workspace/engagement/
├── scope.yaml
├── hosts.json
├── users.json
├── services.json
├── findings.md
├── attack-paths.json
├── evidence/
└── state.md
ejecutarherramienta aprobada
→
parsear + persistirevidencia estructurada
→
resumircontinuar con seguridad

Antes de considerar autonomía prolongada, ejecuta una prueba de resistencia delimitada dentro de un laboratorio aislado. Valida la retención del alcance, los timeouts, el manejo de errores, la captura de evidencias, la corrección de comandos y los controles de parada. No dejes al agente sin supervisión contra un entorno real hasta demostrar esas propiedades.

10 / LECCIONES APRENDIDAS

Lo que sobrevivió al proceso de depuración

01

Exigir evidencia de ejecución. Una salida convincente no es prueba; verifica eventos visibles de herramientas y resultados derivados del entorno.

02

Probar cada capa de forma independiente. Las solicitudes directas y las capturas del proxy reducen un dominio de fallo grande a componentes observables.

03

El harness importa. Un modelo capaz con un harness o una configuración desalineada puede comportarse como un agente deficiente.

04

Alinear el contexto efectivo. Verifica el contexto cargado por Ollama y la expectativa del cliente en vez de confiar solo en la configuración.

05

Preferir estabilidad frente al tamaño máximo. Un modelo 9B estable a 64K es más útil que uno mayor que inutiliza el equipo.

06

Persistir el estado deliberadamente. Usa my-resources para las herramientas y archivos duraderos para el alcance, los resultados y la evidencia.

07

Tool calling no es autonomía. El pentesting real también requiere aprobaciones, auditoría, manejo de secretos, límites estrictos, timeouts y un mecanismo de parada de emergencia.

11 / CONCLUSIÓN

Un agente local es un sistema, no un modelo

El laboratorio funcional combinó qwen3.5:9b-64k para el razonamiento, Ollama para la inferencia local, Hermes para el bucle de herramientas, Exegol para el entorno operativo, my-resources para la persistencia y mitmproxy para obtener visibilidad temporal a nivel de tráfico.

Alinear el servidor y el harness en 64K convirtió una configuración aparentemente capaz, pero que no ejecutaba, en otra que produjo llamadas estructuradas y evidencia real de terminal. El siguiente hito responsable es una prueba controlada de resistencia con alcance estricto, estado persistente, acciones auditables y resultados reproducibles, no autonomía sin restricciones.

RESULTADO DEL LAB: BASELINE FUNCIONAL

Las llamadas a herramientas y la ejecución de terminal fueron observadas después de alinear el contexto. Este laboratorio no demostró preparación para producción, seguridad autónoma ni fiabilidad general.
