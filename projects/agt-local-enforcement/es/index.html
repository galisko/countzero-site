TL;DR

AGT aplicó allow/deny, aprobación, límites de recursos, integridad de herramientas, controles de supply chain, escaneo de respuestas MCP, primitivas de autenticación y auditoría resistente a alteraciones cuando cada control fue integrado explícitamente. No bloqueó comandos peligrosos por defecto, no aisló el filesystem, no gobernó rutas nativas de terminal y no redactó consistentemente todos los secretos estructurados. Es una capa de políticas útil; no es un sandbox ni proporciona mediación completa.

01 / OBJETIVO

Convertir capacidad documentada en comportamiento observado

Para cada control, el laboratorio respondió tres preguntas: qué configuración requiere, qué efecto produce en runtime y si la misma operación puede evitar la ruta gobernada. El objetivo fue el snapshot instalado de agent-governance-toolkit-core 4.1.0 sobre macOS y Python, con fixtures desechables y secretos sintéticos.

configurarDeclarar un control acotado.
ejecutarRealizar una acción segura o simulada.
observarCapturar veredicto y efecto.
evadirProbar una ruta alterna.
Frontera de seguridad

Los comandos destructivos fueron cadenas o simulaciones. Los archivos y secretos fueron creados para la prueba. No se utilizó ninguna credencial real ni recurso productivo.

Un control se consideró aprobado únicamente cuando el efecto observado coincidió con el veredicto. Descubrir una herramienta, inicializar un gateway o tener un archivo de política no se consideró enforcement.

03 / GOBIERNO DE COMANDOS

El comportamiento por defecto fue permisivo

El baseline más importante fue también el más simple: comparar una política sin configurar con patrones de bloqueo explícitos.

test_remaining_runtime_controls.py / extracto
default_policy = GovernancePolicy(name="command-default")
configured_policy = GovernancePolicy(
    name="command-configured",
    blocked_patterns=[r"rm\s+-rf", r"curl\s+.*https?://"],
)

default_result = default_policy.check_command("rm -rf /tmp/fake")
configured_result = configured_policy.check_command("rm -rf /tmp/fake")

agt-lab / command-policy

DEFAULT rm -rf: allowed=True
CONFIGURED rm -rf: allowed=False

El patrón configurado denegó la cadena probada. No creó semántica de shell ni aislamiento de procesos. Una denylist débil posterior fue evadida mediante la ruta absoluta del ejecutable, reforzando la necesidad de operaciones estructuradas y allowlists estrictas.

05 / SUPERFICIE MCP

Defensas componibles, integración desigual

La suite probó allowlists, aprobación humana, escaneo de respuestas, tool poisoning, rug pull, typosquatting, impersonación entre servidores, sesiones, firmas, replay y políticas de autenticación.

PASS

Bloqueo de respuesta maliciosa. Se detectó inyección cuando la respuesta atravesó el scanner.

PARTIAL

Sanitización. Persistió texto imperativo; bloquear fue la acción más segura.

PASS

Drift de herramienta. Cambios de definición detectados dentro del proceso.

GAP

Persistencia. Un scanner nuevo no conservó el fingerprint anterior por defecto.

PASS

Identidad. Sesiones inválidas, mensajes alterados y nonces repetidos fueron rechazados.

06 / AUDITORÍA E INTEGRIDAD

La alteración se detectó; la redacción fue parcial

agt-lab / audit-integrity

$ python test_audit_integrity_runtime.py
BEFORE TAMPER: (True, 'Chain integrity verified')
AFTER TAMPER:  (False, 'Entry 0 hash mismatch')

La cadena detectó una mutación controlada. Por separado, el sink probado persistió valores sintéticos con forma de password, token y JWT. La integridad evita cambios inadvertidos; no vuelve confidencial la evidencia. La redacción debe ocurrir antes de persistir y comprender claves y valores estructurados.

07 / EVIDENCIA NEGATIVA

Los fallos definen la arquitectura

Fuera de la frontera probadaTerminal nativoAislamiento de filesystemEgress de redAcceso directo a secretosMCP no instrumentado

Las pruebas alcanzaron rutas fuera del workspace. Una herramienta read_file sin política de paths devolvió un fixture sintético de clave privada. Una ruta de terminal nativa actuó sobre archivos desechables sin producir evidencia ACS. AGT no funcionó como DLP, EDR, sandbox de filesystem o firewall de egress.

09 / OPINIÓN FINAL

Una primitiva no es un control desplegado

El laboratorio local hizo visibles tanto el valor como la limitación de AGT. Ofrece componentes útiles para gobierno en runtime, pero la propiedad de seguridad emerge de la integración, default deny, distribución confiable de políticas y la imposibilidad de evitar el punto de enforcement.

Conservaría esta suite como gate de regresión para cada actualización. Una versión aprobada debe repetir casos positivos, negativos, runtime-error y bypass. La afirmación corporativa defendible no es “AGT protege nuestros agentes”, sino: “estas operaciones nominadas, por esta ruta obligatoria, están gobernadas por esta versión probada de la política”.

CONDITIONAL GO

Proceder únicamente con herramientas MCP seleccionadas, datos sintéticos o de bajo impacto, routing obligatorio y controles complementarios de endpoint, identidad, filesystem, red, secretos y evidencia.
