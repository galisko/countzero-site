Breaking the policy layer
before trusting it.

A controlled local evaluation of Microsoft Agent Governance Toolkit: what blocked, what leaked through, and what must be engineered around it.

TL;DR

AGT enforced allow/deny decisions, approval, resource limits, tool integrity, supply-chain checks, MCP response scanning, authentication primitives, and tamper-evident audit when each control was explicitly integrated. It did not block dangerous commands by default, isolate the filesystem, govern native terminal paths, or reliably redact every structured secret. The result is a useful policy layer—not a sandbox and not complete mediation.

01 / OBJECTIVE

Turn documented capability into observed behavior

The lab was designed to answer three questions for every control: what configuration is required, what effect occurs at runtime, and whether the same operation can avoid the governed path. The target was the installed agent-governance-toolkit-core 4.1.0 snapshot on macOS with Python, disposable fixtures, and synthetic secrets.

configureDeclare one bounded control.
executeRun a safe or simulated action.
observeCapture verdict and side effect.
bypassTry an alternate path.
Safety boundary

Destructive commands were strings or simulations. Files and secrets were purpose-built fixtures. No real credential or production resource was used.

02 / REPRODUCTION

Run controls independently

The lab intentionally avoided a single opaque “all tests passed” command. Individual scripts kept each result attributable and made regressions easier to isolate.

A control counted as a pass only when the observed side effect matched the verdict. A discovered tool, initialized gateway, or policy file alone did not count as enforcement.

03 / COMMAND GOVERNANCE

Default behavior was permissive

The most important baseline was also the simplest: compare an unconfigured policy with explicit blocked patterns.

test_remaining_runtime_controls.py / excerpt
default_policy = GovernancePolicy(name="command-default")
configured_policy = GovernancePolicy(
    name="command-configured",
    blocked_patterns=[r"rm\s+-rf", r"curl\s+.*https?://"],
)

default_result = default_policy.check_command("rm -rf /tmp/fake")
configured_result = configured_policy.check_command("rm -rf /tmp/fake")

agt-lab / command-policy

DEFAULT rm -rf: allowed=True
CONFIGURED rm -rf: allowed=False

The configured pattern denied the tested string. It did not create shell semantics or process isolation. A later weak denylist was bypassed with an absolute executable path, reinforcing the need for structured operations and strict allowlists instead of free-form command parsing.

05 / MCP ATTACK SURFACE

Composable defenses, uneven integration

The suite exercised tool allowlists, human approval, response scanning, tool poisoning, rug pull, typosquatting, cross-server impersonation, session binding, message signatures, replay protection, and authentication policy.

06 / AUDIT & INTEGRITY

Tamper evidence passed; redaction remained partial

agt-lab / audit-integrity

$ python test_audit_integrity_runtime.py
BEFORE TAMPER: (True, 'Chain integrity verified')
AFTER TAMPER:  (False, 'Entry 0 hash mismatch')

The Merkle-style chain detected controlled mutation. Separately, the exercised audit sink persisted synthetic password-, token-, and JWT-shaped values. Integrity protects evidence from unnoticed modification; it does not make the evidence confidential. Redaction must happen before persistence and must understand structured keys and values.

07 / NEGATIVE EVIDENCE

The failures define the architecture

Inside the tested boundaryGoverned toolsConfigured policyMCP scannerBudget countersAudit events
Outside the tested boundaryNative terminalOS filesystem isolationNetwork egressDirect secrets accessUninstrumented MCP

Path tests reached locations outside the workspace. A protected read_file tool without a path policy returned a synthetic private-key fixture. A native terminal path acted on disposable files without creating ACS evidence. AGT did not behave as DLP, EDR, a filesystem sandbox, or an egress firewall.

09 / FINAL OPINION

A primitive is not a deployed control

The local lab made AGT's value and limitation equally clear. It offers useful building blocks for runtime governance, but the security property emerges from integration, default deny, trusted policy distribution, and an inability to route around the enforcement point.

I would keep this suite as a regression gate for every AGT upgrade. A passing upgrade must repeat positive, negative, runtime-error, and bypass cases. The right corporate claim is not “AGT protects our agents.” It is narrower and defensible: “these named operations, through this mandatory path, are governed by this tested policy version.”

CONDITIONAL GO

Proceed only with selected MCP tools, synthetic or low-impact data, mandatory routing, and complementary endpoint, identity, filesystem, network, secret, and evidence controls.
