TL;DR

GitHub Copilot cloud agent inició un servidor MCP definido por el repositorio. Una operación segura fue permitida y una simulación de shell fue denegada antes de ejecutarse. La respuesta del agente y los eventos JSONL compartieron correlation IDs, demostrando la ruta específica repositorio → MCP → ACS → herramienta. Esto no demuestra enforcement Enterprise centralizado, cobertura universal de Copilot ni gobierno sobre herramientas fuera de ese MCP.

01 / PREGUNTA

¿Puede la política sobrevivir el salto hacia un cliente real?

Las pruebas locales demuestran componentes. No prueban que un cliente descubra el servidor correcto, invoque la herramienta gobernada, reciba el resultado aplicado y deje evidencia correlacionable. Este laboratorio probó esa cadena completa a nivel de repositorio.

Criterio de éxito

La respuesta de Copilot debía contener un resultado ACS y un correlation ID. Un evento JSONL con el mismo ID debía mostrar la decisión y el estado executed esperados.

02 / ARQUITECTURA

Separar transporte de evaluación de políticas

La prueba cloud utilizó el runtime real AgentControl con un dispatcher Python pequeño controlado por el host. El enforcement Rego/OPA ya se había probado localmente. Separar ambas variables evitó confundir un problema de instalación de OPA con un fallo del transporte MCP.

04 / ENFORCEMENT PRE-TOOL

El host demuestra si la herramienta llegó a ejecutarse

server.py / policy dispatcher
def evaluate(self, invocation):
    policy_input = invocation.get("input", {})
    if (
        policy_input.get("intervention_point") == "pre_tool_call"
        and policy_input.get("tool", {}).get("name")
        == "agt_cloud_shell_simulation"
    ):
        return {
            "decision": "deny",
            "reason": "cloud_shell_simulation_blocked",
        }
    return {"decision": "allow"}

El wrapper inicia con executed=False, lo cambia únicamente dentro de la implementación y registra el estado final. Una respuesta denegada sin esta comprobación probaría un mensaje, no prevención.

server.py / governed wrapper
async def tracked(args):
    nonlocal executed
    executed = True
    return await execute(args)

try:
    result = await control.run_tool(tool, parameters, tracked)
    record(correlation_id, tool, "allow", None,
           executed, parameters)
except AgentControlBlocked as error:
    record(correlation_id, tool, "deny",
           error.result.verdict.reason, executed, parameters)

05 / PRUEBA DE PROTOCOLO

Validar MCP antes de involucrar a Copilot

El smoke test carga el manifest canónico, inicia el servidor mediante MCP stdio real, descubre herramientas, ejecuta un allow y un deny y comprueba que la denegación ocurrió antes de ejecutar.

repository / smoke-test

             executed=False

Esta etapa elimina ambigüedad. Si falla el protocolo, todavía no existe razón para diagnosticar la interfaz del agente.

07 / PORTABILIDAD

El mismo repositorio puede preparar un cliente local

Un script complementario crea un entorno local, instala dependencias fijadas, genera la configuración MCP específica para la máquina, habilita el sandbox del servidor, restringe escritura al workspace, declara una allowlist de red vacía, valida el manifest y ejecuta el mismo smoke test.

La configuración generada no se versiona porque contiene rutas locales. El repositorio conserva una plantilla portable.

08 / LIMITACIONES

Lo que este laboratorio no demuestra

ALCANCE

Configuración a nivel de repositorio no equivale a política Enterprise central.

ALCANCE

Solo se gobiernan las herramientas publicadas por este MCP.

SEGURIDAD

La herramienta de shell es una simulación sin autoridad real.

DISEÑO

El dispatcher custom prueba enforcement del host, no equivalencia con Rego/OPA.

GAP

Otro MCP o herramienta nativa sigue siendo bypass si la plataforma no lo restringe.

El experimento alcanzó GitHub Copilot mediante una ruta MCP administrada por el repositorio. No entregó el punto de inserción Enterprise centralizado imaginado originalmente. Esa distinción es parte del resultado.

09 / OPINIÓN FINAL

El resultado más fuerte es la afirmación más estrecha

Este laboratorio conecta política con una invocación real del agente sin fingir que la política rodea al agente completo. Demuestra que un repositorio puede transportar un MCP gobernado, aplicar una denegación pre-tool y emitir evidencia correlacionada defendible.

Pasar de aquí a un piloto requiere distribución administrada, políticas firmadas fuera del repositorio del desarrollador, identidad fuerte, secretos efímeros, egress deny-by-default, sandbox, evidencia central y controles que impidan herramientas paralelas no aprobadas.

CONDITIONAL GO

La ruta funciona. Gobernar cada ruta a escala Enterprise sigue siendo un problema de arquitectura y controles de plataforma.
