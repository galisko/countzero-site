TL;DR

GitHub Copilot's cloud agent started an MCP server defined by the repository. A safe operation was allowed and a shell simulation was denied before execution. Agent output and JSONL events shared correlation IDs, proving the specific repository → MCP → ACS → tool path. This does not prove centralized Enterprise enforcement, universal Copilot coverage, or governance over tools outside that MCP server.

01 / RESEARCH QUESTION

Can policy survive the jump to a real agent client?

Local unit tests prove components. They do not prove that a client discovers the right server, invokes the governed tool, receives the enforced result, and leaves evidence that can be correlated. This lab tested that complete chain at repository scope.

Success criterion

A Copilot response had to contain an ACS result and correlation ID. A JSONL event with the same ID had to show the expected decision and executed state.

02 / ARCHITECTURE

Separate transport from policy evaluation

The cloud test used the real AgentControl runtime with a small host-owned Python dispatcher. Rego/OPA enforcement had already been tested locally. Keeping those variables separate prevented an OPA installation problem from being misdiagnosed as an MCP transport failure.

04 / PRE-TOOL ENFORCEMENT

The host proves whether the tool executed

server.py / policy dispatcher
def evaluate(self, invocation):
    policy_input = invocation.get("input", {})
    if (
        policy_input.get("intervention_point") == "pre_tool_call"
        and policy_input.get("tool", {}).get("name")
        == "agt_cloud_shell_simulation"
    ):
        return {
            "decision": "deny",
            "reason": "cloud_shell_simulation_blocked",
        }
    return {"decision": "allow"}

The wrapper sets executed=False, flips it only inside the actual implementation, and records the final state. A denied response without this check would prove a message, not prevention.

server.py / governed wrapper
async def tracked(args):
    nonlocal executed
    executed = True
    return await execute(args)

try:
    result = await control.run_tool(tool, parameters, tracked)
    record(correlation_id, tool, "allow", None,
           executed, parameters)
except AgentControlBlocked as error:
    record(correlation_id, tool, "deny",
           error.result.verdict.reason, executed, parameters)

Validate MCP before involving Copilot

The smoke test loads the canonical manifest, starts the server over real MCP stdio, lists tools, calls one allowed operation and one denied simulation, then asserts that denial occurred before execution.

The same repository can bootstrap a local client

08 / LIMITATIONS

What this lab does not prove

SCOPE

Repository-level configuration is not centralized Enterprise policy.

SCOPE

Only tools published through this MCP are governed.

SAFETY

The shell tool is a simulation; it receives no real system authority.

DESIGN

The custom dispatcher proves host enforcement, not equivalence with Rego/OPA.

GAP

An alternate MCP or native tool remains a bypass unless the platform restricts it.

The experiment reached GitHub Copilot through a repository-managed MCP path. It did not deliver the centrally governed Enterprise insertion point originally envisioned. That distinction is part of the result, not a footnote.

09 / FINAL OPINION

The strongest result is the narrowest claim

This lab links policy to a real agent invocation without pretending that the policy surrounds the entire agent. It proves that a repository can carry a governed MCP, enforce pre-tool denial, and emit defensible correlated evidence.

Moving from this result to a corporate pilot requires managed distribution, policy signing outside the developer repository, strong workload identity, ephemeral secrets, deny-by-default egress, sandboxing, central evidence, and controls that prevent unapproved parallel tools.

CONDITIONAL GO

The route works. Enterprise governance of every route remains an architecture and platform-control problem.
